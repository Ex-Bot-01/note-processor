## 2. Track A — the hardening backlog, in the order to take it

Each item is its own branch off `main`, with a design note reviewed **before** code. Sizes below are honest: F24 and F17 are
afternoon work; the identity design is not.

**Shipped 2026-10-27 (`af1d504`).** The design review caught an acceptance criterion that could not be checked, and the
implementation review caught a summed premise assertion that left three of four residue zeros vacuous; both were fixed before
merge. What follows is kept as the record of how the item was framed.

### A1 · F24 — merge assertions duplicated across the two fixtures (branch `m7/f24-merge-assertions`)

`docs/backlog-m2-followups.md:464`. `merging_a_duplicate_pair_keeps_the_oldest_id_and_moves_every_incoming_edge` and
`a_version_three_file_jumps_four_to_five_in_one_open_and_its_pair_merges` repeat five blocks. The backlog's warning is the
design constraint: **do not flatten the failure messages**, because "the edge crossed the rebuild and the merge together" is
not the claim the version-four case makes. The shape that satisfies both is *measure once, assert separately*: a helper
returns the observed facts (survivor ids, per-shape loser counts, incoming-edge target, receipt string) and each test keeps
its own `assert_eq!` with its own message. Duplication of query text — the thing that drifted last round — goes away; the
distinct claims stay visible.

Acceptance: both fixtures reach each measured fact through one call site (a third pre-merge variant of the incoming-edge query
stays, it is a different claim); assert counts do not fall (baseline 9 and 9 in the fixtures, 1 and 1 in the seeders); and
per-fact **production** mutations — stop re-pointing edges, skip the loser's derived-row deletes, keep the loser row — each
turn both fixtures red. "Delete an assertion and see who fails" is not a check: removal makes tests pass.

**Shipped 2026-10-27 (`0f85811`).** Refused at load rather than clamped, bound 0..=16, carried as `Io(InvalidData)`; the
item was worse than filed because the indent reaches `" ".repeat()` and an addition. What follows is the framing it was
worked from.

### A2 · F17 — `continuation_indent` accepted unclamped (branch `m8/indent-clamp`)

`docs/backlog-m2-followups.md:225`. `config.rs` takes any `usize`, and `wrap` charges it as the prefix of every continuation
line, so an indent near or above `COLUMN_LIMIT` puts every line over budget before its first token — a typo in `config.toml`
quietly yields one-token-per-line output. The decision to make in the design note is **reject or clamp**, and the backlog's
own suggestion is a documented maximum around 16; whichever is chosen, the error must name the key (the item's "done when"
is that `np scan` fails with a message naming the key instead of rendering oddly). Acceptance: oversized values refused at
config load quoting the offending value and the accepted range; the boundary value itself accepted; existing goldens unmoved,
because the default path must not change.

**Shipped 2026-10-28 (`d264e45`).** Added rather than regenerated, and the first fixture failed its own mutation -- see
`docs/design-f16-wide-goldens.md` §4 for what that taught. Filing **F25** came out of it: an over-wide token renders a physical
line holding only the bullet, still unadjudicated.

### A3 · F16 — no wide-character fixture in the golden corpus (branch `m9/wide-goldens`)

`docs/backlog-m2-followups.md:212`. Wrapping and alignment count characters, not display width (F12 shipped the fix; nothing
in the corpus would notice a regression). **Goldens are never regenerated** — this item adds *new* fixture files and their
own goldens, it does not touch one byte of the existing ones, and any `tests/golden/` diff outside the new files is a
stop-and-report. Decide first whether the corpus needs East-Asian wide glyphs, combining marks, and ZWJ sequences or one
representative file each; more than that is maintenance without signal.

**Shipped 2026-10-28 (`cbcb12a`), merged on your word.** The two debts it left stand and are named in §5: no A/B/A benchmark, no
whole-branch review. What follows is the framing it was worked from.

### A4 · Durable file identity — the shared root of F20's residue and F23's residue

Both designs now name the same cause: a registry key derived from display text cannot say which byte spelling, or which
physical file, it belongs to. F23 healed the half where content still agrees; a migration-keyed row whose content changed
while unindexable stays duplicated until the obstruction clears (`design-f23` §6). The way through is an OS-level identity —
`st_ino`/`st_dev` on Unix, volume serial + file index on NTFS — stored per file row and used as a *third* matching route
beside identity and content.

This needs a real design note and a design review before code, and it carries F18's rule without exception: **no Windows
claim until one runs on Windows.** CI does run `windows-latest`, but the NTFS identity fields need a probe that asserts them
on a Windows host with the fixture actually planted; until such a run is recorded with host, euid, head SHA and command, the
Windows half stays unimplemented rather than speculative. Decide explicitly, in the design, what happens when identity is
unavailable (same filesystem across a bind mount, `noac` NFS, copied workspace): identity may add a match, never remove one.

### A5 · F18's Windows byte identity (blocked on hardware, not on thought)

`docs/backlog-m2-followups.md:268`. Same blocker as A4's second half. Nothing to schedule; note it in any design that
touches path bytes.

### Things people assume exist, and don't

- **Nothing reads vectors.** Catalog, links, tags and items never touch `embeddings` — a deliberate fence that kept the goldens frozen
  and let M2a merge before the model question was answered.
- **No command answers "which chunks are embedded?"** Coverage is recorded (`EMBED_VERSION_KEY`) and a gap prints one stderr line;
  per-chunk visibility stays an open debt.
- **Deleting a `models` row cascades its vectors**, and no command deletes model rows today — know that before the width-narrowing
  migration (local-embeddings §5), which needs exactly that operation.

### The four things waiting on you, not on me

1. **"First start" shape** — daemon-only auto-fetch (recommended: nothing else should dial out because a config value named a model), or
   the first command that needs vectors starts it, with a consent line and `--no-fetch`.
2. **Daily-file layout** — `YYYY-MM-DD.md` at the corpus root vs a `daily/` directory (#10).
3. **Is `processed/` authoritative or disposable?** (#11) — decides whether compression output is indexed, backed up, or regenerable.
4. **Search shape** — vector-only first (#1), or hybrid with FTS5 from the start (#5). Hybrid costs a migration and one derived-text
   path; vector-only leaves exact-phrase recall on the table until later.

### Standing debts shaped like features

A4 merged without its A/B/A benchmark or whole-branch review · F18's Windows byte identity still needs real hardware (CI proves
inertness, nothing more) · F25: an over-wide token can render a line holding only `-` · the chunker has no overlap between chunks and is
fence-blind (a fenced block containing a blank line can split in half) · wrong-dim provider handling and concurrent-install atomicity are

## 4. Protocol — how work gets done here (do not skip this under time pressure)

1. **Design note first** (`docs/design-fNN-*.md`), reviewed by a fresh reviewer before any code. Two of F23's three review
   rounds blocked the *design*; that was cheap on paper and would have been expensive mid-round.
2. **Fresh implementer per bounded round, fresh scoped reviewer after each**, fix loop for Critical/Important, one broad
   whole-branch review at the end. Two writers never share a worktree; `db.rs` / `scan.rs` rounds serialize behind reviews.
3. **Checkpoint before prose.** Commit a `wip:` commit as soon as the tree compiles — never hold finished work uncommitted.
   Endpoint timeouts have cost this project seven rescued rounds; narrow scope is the only mitigation that works.
4. **A reviewer has no shell.** It states "static read" and lists commands; it never reports gate or mutation results it did
   not produce (two rounds fabricated them). The controller independently executes load-bearing claims.
5. **A subordinate's evidence outranks a controller's instruction.** When M5's implementer refused a prescribed fixture as
   unreachable, it was right; refuse and explain rather than fake coverage. Unreachable pins get documented as
   defence-in-depth, not simulated (`notes.rel_bytes` CHECK makes a NULL key unrepresentable; `writable_schema` was refused).
6. **Mutation protocol:** copy the file to `/tmp`, mutate, restore from the copy — never `git checkout --`. A test that
   passes under its own mutation is vacuous and gets rewritten or deleted.
7. **Goldens are never regenerated.** Any diff in `tests/golden/` stops the round and gets reported.

### The gate list (fixed, no subsetting)


**Aggregate suites by exit code plus `grep -cE '^test result: FAILED'`** — never by awk over `test result` lines: a FAILED
line has a different field layout, and that mistake once reported 275/0 while a suite was failing. Check per-binary counts
and that the total did not drop against baseline.

Fixtures that depend on `chmod 000` must re-check the denial off disk and print `NOT COVERAGE` when it did not happen; any
claim about them records **command, head SHA, host and euid** (`uname -n`, `id -u`) — "this runner" is not an identification.
Hot-path changes get an A/B/A benchmark against the merge base, always stating what the benchmark cannot see.

## 3C. Prototype 1 — what we are steering toward now (set 2026-10-29)

You set the direction: **steer toward the first prototype.** That is a priority rule, not a new feature list, and it changes three things about
how rounds get chosen from here.

**What Prototype 1 is.** The smallest thing that earns its keep on your real corpus (~1,500 notes), used from a terminal, one machine, no daemon:

```
np scan <ws>        # already shipped — the index and INDEX.md
np models fetch …   # R7b, or `install --path` today — get the artifact onto the disk
np embed <ws>       # R6c — every chunk gets a vector
np search <ws> "…"  # NEW: ranked notes with file paths, sizes and why they matched
```

**In scope until it exists:** local inference (R6b), writing vectors (R6c), the first `np search` with honest ranking and evidence, the fetch +
marker path (R7a/R7b) so a fresh machine can be set up without hand-copying files, and the benchmark (R6d) that says whether this is usable at
18k chunks.

**Out of scope until Prototype 1 runs:** clustering and the review queue (M2b), `processed/` compression (M2c), daily files and timelines (M3),
daemon/watcher/API (M4), any UI (M5/M6), chat (phase 2), and multimodal beyond keeping the *plumbing* multi-file so R7c can happen. Hardening
continues only where it blocks the above — goldens, refusal-over-repair, and the gate list are not "polish", they are how the prototype stays
trustworthy; F25-style cosmetics wait.

**What the steer surfaced immediately.** The first thing prototype work has to answer is "can we run the model at all", and that check failed:
the pinned Rust binding's vendored llama.cpp does not know `gemma-embedding2` (design §13 has the greps, the missing `cmake`, and the three
shapes with their prices). A prototype forces that question into the open on day one instead of at merge time — which is the argument for the
steer, and also its cost: it is now a decision about **which model** the prototype embeds with, and that one is yours.

**Rule I will apply when picking the next round:** if two rounds are equally sound, take the one that puts a queryable vector in front of you
sooner — and say out loud what is being deferred, so nothing gets quietly dropped.
