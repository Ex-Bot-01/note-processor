## Images

Generated by `crates/np-core/tests/probes/gen_vision_images.py` (stdlib only: no Pillow on this host) into
`crates/np-core/tests/probes/vision/`: a red square on white and blue/white diagonal stripes, each at 1024×768 and 512×384.
**No text was rendered** — no font is guaranteed here, and the comparability question does not need it.

## The four answers

1. **Token cost of one image: it scales with resolution, and it is not the card's flat 280.** 1024×768 → **336** image
   tokens; 512×384 → **88**; both in 3 chunks. The model card publishes 280 as a *default* for its reference implementation;
   this builder sizes the patch grid from the image, so a diagram's cost has to be measured per encode — which is exactly
   what §8's `over-budget` rule says to do rather than compute from file size. Even at the largest size tried, one image is
   4 % of the 8,192-token window.
2. **The soft-token budget is honoured.** `mtmd_context_params.image_min_tokens / image_max_tokens` are wired through: with
   min/max = 70/70 the small image dropped from 88 to **63** tokens; raising max to 1120 left it at 88, because the budget is
   an upper bound and the native grid for that image is smaller. So the card's quality/token trade exists in this runtime,
   but nothing in R7c needs it — leave both unset (`-1`) and take the native grid.
3. **Pooled width: 768**, read back from the C side as `llama_model_n_embd_out`, matching the artifact's
   `n_embd_inp = 512` / `n_embd_out = 768`. The pooled row arrives un-normalised (`L2 norm = 180.17` on one run), so the
   caller must L2-normalise — same contract as the text path, and §10's "pool at out, normalise" is what the runtime expects.
4. **Comparability: yes, on these synthetic pairs.** Every caption beat an unrelated control sentence against its own image,
   and each caption's best-matching image was the right one:

| Caption | best (own image) | vs unrelated control | other image |
|---|---|---|---|
| "a red square on a white background" | **+0.7465** | +0.6051 | +0.5578 |
| "blue and white diagonal stripes" | **+0.7675** (1024×768); +0.7774 is the 512×384 copy — see the correction below | +0.6237 | +0.5630 |

**Corrected 2026-11-04 (Task 8), and only this annotation.** This row used to read "+0.7675 / +0.7774 (two runs)", which is not
what the log below shows: RUN A lists item 3 as `vision/stripes_512x384.png`, a different bitmap from item 1's
`stripes_1024x768.png`, so +0.7774 is the caption matching the *smaller copy of its own figure* — a second pairing, not a second
measurement of the first. Nothing here was measured twice, which matters because §8 of `docs/design-m2-local-embeddings.md`
forbids quoting one run as a spread. The orderings and every number stand; the transcript at the bottom is untouched, since it
is the evidence this correction is drawn from. Re-measured through the shipped Rust seam on 2026-11-04 (twice, identical to six
decimals): own image +0.746469 against other image +0.557844 for the red-square row — design §14.3.

   Also visible in the matrix: image-to-image cosine (+0.7295 for the two 1024×768 images) is high, and text-to-text
   (+0.6051 … +0.6440) sits in the same band — consistent with one shared space rather than two geometries, which is what
   §12's single ranked list assumes. **This is not a retrieval-quality result**: four synthetic shapes and three sentences
   prove the plumbing reaches both kinds and ranks them sensibly. A labelled diagram set is still owed (§14).

## Runtime facts worth carrying into Task 4

```text
mtmd.support_vision     = true
mtmd.support_audio      = true        (unused here; mtmd also warm-loads an audio path)
mtmd.default_marker     = "<__media__>"
mtmd.decode_use_mrope   = false       → no M-RoPE position juggling needed for images on this architecture
mtmd.use_non_causal(img)= true        → the probe sets causal_attn=false around the image decode and restores it after
ctx.pooling             = MEAN        (the artifact's own default; matches the card's "mean pooling")
```

The non-causal restore is load-bearing, not cosmetic: `llama_set_causal_attn` is flipped for the image decode and put back
afterwards, so a text encode later in the same process is unaffected. A Rust seam that forgot the restore would make text
vectors quietly wrong while every image vector looked fine.

**One trap found on the way.** The probe with zero `ITEM` arguments prints its header, an empty pairwise table, and exits 0.
That is a silent no-op — a driver that forgot to pass images would report success. Any CI or script row driving this probe
must pass items explicitly and check for at least one `image tokens` line.
